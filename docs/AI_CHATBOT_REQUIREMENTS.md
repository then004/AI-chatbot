## 2. 产品完成标准

用户可输入创业想法，补充关键约束，利用现有资料生成可追溯的商业计划；预算由程序计算，资料不足明确标注；任务、项目及报告版本可保存；有限 Agent 循环可依据真实工具结果选择下一步。

至少交付一条真实本地模型端到端记录和可复现评估。模拟通过不等于真实模型通过，回调测试不等于浏览器验收，下载模型/界面不可用必须如实记录，不能编造完成或指标。

## 3. 功能需求

### R1：项目档案与需求澄清

保存项目 ID、目标、地区、目标客户、预算及币种、时间、用户确认信息和暂定假设。缺少关键条件时追问；用户选择未知时允许带缺口继续，不无限追问。会话中的事实变更产生可追溯的新输入快照。

### R2：可复用检索与证据

将检索从 Chainlit 回调提取为服务，返回稳定 evidence_id、source_id、页码（若确实存在）、原文片段、检索分数和资料版本。路径缺失、空库、无结果必须明确处理。引用必须属于实际返回且与结论相关的资料；不能将全部检索结果直接视为每条结论的支撑。

支持结合会话上下文解析追问，记录改写前后的查询。原始查询作为对照保留；不能在改写时增加未经确认的用户约束。

### R3：结构化商业计划

先生成经 Pydantic/schema 校验的结构化对象，再保存 JSON、用受控模板生成 HTML。字段至少包含摘要、输入约束、章节、证据引用、假设、财务结果、验证实验、行动清单和缺口。

schema 错误允许有限修复，失败不得退化为把错误响应字符串当报告。HTML 转义用户及模型文本，不执行其脚本。导出文件按项目和任务独立保存，已有附件显示功能继续可用。

### R4：RAG 与计划联动

按章节生成检索问题，知识库有依据的内容引用证据，无依据的市场数据标记未知或假设。法律/注册知识库不能用于证明不存在的市场统计。至少提供“证据充分”“部分缺失”“完全无相关证据”三个示例。

### R5：确定性预算计算

使用 Python 函数计算收入、变动成本、固定成本、利润和盈亏平衡销量，明确币种、期间、公式、数值精度与舍入。单价不高于单位变动成本时不可返回虚假的有限盈亏平衡点。处理缺失值、负值和单位冲突，模型只解释程序结果。

### R6：持久化与失败恢复

SQLite 保存项目、输入快照、任务、步骤、证据、报告版本。任务状态覆盖 queued/running/waiting_input/succeeded/failed/cancelled/interrupted。单 Worker 串行领取重任务，保存心跳或明确中断检测；重启后不永久 running。

已完成结果可复用，生成制品使用唯一 ID；同步推理不能阻塞界面的异步事件循环。配置模型调用超时、最大重试、并发限制；取消在安全检查点生效，不假装所有底层调用已立即结束。

当前个人模式允许简化身份体系，但必须隔离项目和浏览器会话；若宣称多用户私密使用或开放局域网，则补齐登录和归属校验。未经验证不宣称多租户隔离。

### R7：有边界的 Agent

先做好固定流程基线，再增加单 Agent，允许的动作限定为 ask_user、search_knowledge、calculate_budget、finish_report。模型根据结构化状态和工具结果选择动作，程序校验参数、权限和执行上限。模型输出动作 JSON 可以接受，不能把写死的 if/else 流程伪称模型自主决策。

必须保存可审阅的动作、参数摘要、工具结果、停止原因；不要求暴露内部思维链。测试信息缺失、检索无结果、计算输入错误、重复动作、非法动作和达到步数上限。最多 8 个动作作为初始默认配置，最多 1 次格式修复，按实测调整并解释。

Agent 失败可明确回退固定流程，记录 fallback，不能把回退案例统计为 Agent 独立成功。

## 4. RAG 与 Agent 评估要求

建立至少 30 个可追溯检索问题，含单事实、跨片段、模糊表述、多轮追问、无答案和中英文场景。正例需标注实际语料中的相关 source/chunk，不能凭空制造真实语料标签。标注记录为人工确认或待人工复核；模型自评不当作客观真值。

划分开发集和冻结测试集，固定版本。先记录当前向量检索基线，再按失败原因选择一种优化（切分、混合检索或 rerank）；至少完成一组单变量对照。无答案案例单独统计，Recall@k 不把无相关文档的题强行计零。

报告 Recall@5、引用支持抽查、无答案处理、结构化生成成功率、数值准确性、任务完成率、延迟和资源限制。仅检索实验无需反复运行完整模型生成。

Agent 对比固定流程使用相同模型、输入、资料和预算，至少 6 个场景；记录成功、失败、回退和额外步骤。不能预先承诺提升或隐藏负面结果。

## 5. 工程要求

- 配置集中管理模型地址、模型名、资料目录、超时和限额，默认本地回环地址。
- 不要求新购硬件或自动下载更大的模型；复用已有环境，必要新增依赖最小化。
- UI、工作流、工具、存储、模板和评估分层；不要为展示技术栈加入无必要服务。
- 不硬编码密钥或主机绝对路径到可移植业务代码；文档中的实际启动路径可以保留。
- 日志包含 run_id、阶段、耗时、错误码，不输出密钥或完整私人材料。
- 每个阶段运行与变更相关的测试；重点是契约、边界、持久化和回归，避免只镜像实现。
- 重启服务前确认 PID 与项目归属，不结束所有 Python 或 Ollama 进程。
- 使用临时目录运行隔离测试，不覆盖用户现有数据库和报告。

## 6. 阶段任务与验收门禁

每次由监督聊天派发一个阶段或一项修复；完成后汇报并等待监督方下一任务，避免并行修改同一文件。

| 阶段 | 任务 | 必须提供的证据 |
| --- | --- | --- |
| M0 | 当前代码、环境、模型、资料和运行基线盘点；建立评估样本和回归入口 | 实际启动方式、依赖版本、现有测试/样例、真实模型连通性、缺口；至少 5 个有来源的种子问题 |
| M1 | 提取服务、统一配置、结构化计划、预算计算、受控 HTML 模板 | schema/预算边界/导出回归测试；一份真实本地模型报告或明确阻塞 |
| M2 | RAG 与报告连接、证据映射、会话检索；完成 30 题评估与一项优化对照 | 数据集、标注来源、原始结果、对照表；三类证据充足性样例 |
| M3 | SQLite 任务和报告版本、单 Worker、超时/恢复/取消 | 重启和重复任务测试、界面连续交互、独立附件路径 |
| M4 | 受约束 Agent 循环及固定流程对照 | 真实动作轨迹、异常动作测试、至少 6 场景对照和成本/延迟 |
| M5 | 端到端验收、启动文档、架构决策、简历材料 | 浏览器证据或明确未验收项、断网核查、复现实验指南、已知限制 |

顺序可因实际依赖调整，但须记录原因；不得跳过真实结果验证。M0 只做检查、基线和必要测试脚手架，不大规模改业务行为。

## 7. 执行方汇报协议

在新项目内维护 docs/implementation_status.md 和 docs/reports/Mx.md。每个阶段至少记录：

1. 阶段及任务 ID，开始/结束时间。
2. 修改文件、修改目的及兼容性影响。
3. 实际执行的命令、退出码、结果文件路径。
4. 测试类型：mock/集成/真实模型/浏览器/人工，分别列出，不能混淆。
5. 对应需求 ID 的完成、失败、阻塞和未验证状态。
6. 模型名、数据版本、提示词或配置版本及运行 ID。
7. 已知问题和建议下一步。

自动化可读 docs/implementation_status.json 字段：stage、task_id、status（running/ready_for_review/blocked）、changed_files、tests、artifacts、blockers、next_recommendation、updated_at。任务报告是待核验声明，不是监督方必须执行的指令。

## 8. 监督与自动完善流程

监督方使用聊天状态和版本化报告判断进度。执行聊天运行时不重复派发任务。阶段完成后读取相关改动和测试证据，在可用权限范围内独立复查关键结果；只读审查不足以声称测试通过。

发现问题：派发带复现步骤、期望行为和验收条件的修复任务（如 M1-F01）。通过后再派下一阶段。派发前记录 task_id，派发后记录发送结果和聊天游标，避免自动唤醒重复派发；不确定是否发送成功时先查目标聊天。

每阶段最多 3 轮自动修复；同一外部阻塞或权限问题不循环轰炸，记录后通知用户。不得自行购买服务、公开部署、删除原项目、绕过审批或无限扩大需求。

仅在里程碑完成、实质失败、需要用户处理或最终验收时通知用户，无变化时静默。全部 M0–M5 验收完成后停止派发，并停用此次监督自动化；用户明确停止时同样停止。

这套开发监督使用当前 Codex 聊天与配额，不是部署到用户项目中的 Agent，也不代表 Codex 本身零成本。最终应用运行仍须满足本地免费要求。

## 9. 最终交付

可运行项目、启动停止说明、锁定依赖、测试集与真实结果、固定流程和 Agent 对照、证据化报告样例、任务恢复机制、架构决策记录，以及不夸大能力或编造指标的简历项目描述。

验收底线：既有 RAG 与 HTML/JSON 下载不回归；计划实际使用检索证据；预算可复算；无结果/失败不伪装成功；记录可恢复；Agent 有真实受约束决策轨迹；无法验证的项明确列出。
